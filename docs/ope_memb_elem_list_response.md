# `/ope/MEMB` 요소 목록 Key 재검증 회신 (2026-09-06)

요청받은 대로 다시 확인했습니다. **문서 근거 쪽은 우리 노트가 맞고, 요청서의 전제가
틀렸습니다.** 다만 확인 과정에서 아직 아무도 제보하지 않은 별개 오타를 하나
찾았고, 실측 쪽에는 요청하신 질문 5개 중 3개를 답할 기록이 **실제로 없습니다.**
아래에 셋 다 분리해서 적었습니다.

---

## 1. 원문 재확인 — 요청 예제는 `ELEM_LIST`입니다

아티클 `49514964272665`("Member Assignment")를 2026-09-06에 다시 받아
확인했습니다. `updated_at`은 **2026-07-30T05:16:25Z** 로, 요청서에 적힌 최종
편집 시점과 같습니다. 즉 8/27 시점과 같은 판본이 맞습니다.

재현 명령 (공개 엔드포인트, 인증 불필요):

```bash
curl -s "https://support.midasuser.com/api/v2/help_center/en-us/articles/49514964272665.json"
```

`article.body`의 HTML 태그를 제거하고 순서대로 읽으면 이렇게 나옵니다:

| 위치 | 구간 | 내용 |
| --- | --- | --- |
| 4–16 | **Input JSON format example** | `"ASSIGN_TYPE": "MANUAL"`, `"SELECTION_TYPE": "SELECTION"`, **`"ELEM_LIST": [640, 692]`**, `"ALLOW_SINGLE": false` |
| 17–23 | Input JSON format example (2번째) | `"ASSIGN_TYPE": "AUTO"`, `"SELECTION_TYPE": "ALL"`, `"ALLOW_SINGLE": true` — 요소 목록 없음 |
| 24–42 | **Output JSON format example** | `"MEMB" → "1" → **"AELEM"**: [640, 692], "bREVERSE": false` |
| 43–78 | Specifications | 3행 `Element List` / **`"ELEM_LIST"`** / Array / — / `Required(*)` |

본문 전체 문자열 출현 횟수도 같이 세었습니다: **`ELEM_LIST` 2회**(요청 예제 1,
표 1), **`AELEM` 1회**(응답 예제만), `640` 2회 / `692` 5회.

정리하면:

- **`[640, 692]`는 우리 매뉴얼의 예제 값이 아니라 원문 값입니다.** 요청 예제와
  응답 예제 양쪽에 그대로 들어 있습니다.
- **표와 요청 예제는 서로 어긋나 있지 않습니다.** 둘 다 `ELEM_LIST`이고,
  `AELEM`은 응답 예제에만 나옵니다.
- 요청서에 인용된 `"AELEM": [1, 2]` 형태의 요청 예제는 이 아티클 본문에
  없습니다.

`AELEM`을 쓰는 엔드포인트는 따로 있습니다 — **`/db/MEMB` (Design Member
Assignment, 24장)** 이고, 그쪽은 `"Assign"` 래퍼에 id-keyed 레코드이며 필드가
`AELEM` / `bREVERSE` 두 개입니다. 이름이 거의 같아서 혼동하기 쉬운 쌍이고, 저희
SDK도 두 엔드포인트를 각각 다른 키로 구현하고 있습니다
(`midas_nx.ope.MemberAssignmentArgument` → `ELEM_LIST`,
`midas_nx.db.design` → `AELEM`).

## 2. 확인 과정에서 나온 별개 오타 — `"SELETION_TYPE"`

원문 Specifications 표 **2행의 Key가 `"SELETION_TYPE"`** 입니다. C가 빠져
있습니다. 같은 아티클의 요청 예제 두 개는 모두 `"SELECTION_TYPE"`으로 정상이고,
실제 API도 `SELECTION_TYPE`을 받습니다.

우리 벤더드 매뉴얼은 이미 정상 철자로 정규화해 두었기 때문에 지금까지 아무도
보지 못한 항목입니다. 제보 대상으로는 이쪽이 실재하는 결함입니다.

## 3. 실측 쪽 — 답할 수 있는 것과, 기록이 없는 것

실측 결과 자체(`ELEM_LIST` 성공 / `AELEM` 거부)는 유지합니다. 다만 **당시
기록이 남긴 범위가 요청하신 5개 질문을 다 덮지 못합니다.** 있는 그대로 적습니다.

| 질문 | 답 | 근거 |
| --- | --- | --- |
| 테스트 시 `SELECTION_TYPE` 값 | `"SELECTION"` | `src/midas_nx/ope.py`의 docstring이 시험한 페이로드를 그대로 적어두었습니다: `{"ELEM_LIST": [1, 2], ...}` 성공 / `{"AELEM": [1, 2], ...}` 실패. 두 요청 모두 `SELECTION_TYPE="SELECTION"`, `ALLOW_SINGLE=false` |
| `AELEM` 거부 시 HTTP 상태 코드와 응답 전문 | **기록 없음** | 남은 것은 메시지 문자열 `"There is no valid element information."` 뿐입니다. 상태 코드도 본문 전문도 적어두지 않았습니다 |
| 두 키를 동시에 보냈을 때의 동작 | **시험한 적 없음** | 그 조합은 검증 대상이 아니었습니다 |
| 테스트한 제품 빌드 | **그 테스트에 대해서는 기록 없음** | `docs/coverage.json`의 `/ope/MEMB` 항목이 담고 있는 것은 2026-07-30의 별개 프로브(`ASSIGN_TYPE=AUTO`, `SELECTION_TYPE=ALL`, Gen NX v2.1 build 07/28/2026 / Civil NX v2.2 build 07/29/2026)이고 `level`도 아직 `read`입니다. 8/27의 `SELECTION` 테스트는 원장에 반영되지 않았습니다 |
| 성공 시 GET 응답이 `AELEM`으로 돌아오는지 | **POST 응답**은 `{"AELEM": [1, 2], "bREVERSE": false}`로 돌아왔습니다. 별도 GET은 기록 없음 | 원문 응답 예제와 일치합니다 |

**이 테스트는 `scripts/live_crud_check.py`에 케이스로 들어가 있지 않습니다.**
그래서 기계적으로 재실행할 수가 없고, 위 세 칸을 채우려면 사람이 붙는 새 라이브
세션이 필요합니다. 저희 쪽 기록 관리의 공백이 맞고, 그렇게 적어두겠습니다.

## 4. Jira 제보(A-7)에 대한 의견

요청서의 걱정 방향은 정확했는데, 결론이 반대입니다.

현재 제보는 **"표의 `ELEM_LIST`를 `AELEM`으로 고쳐달라"** 인데, 표는 지금
맞습니다. 요청 예제도 맞습니다. 요청서가 대안으로 제시한 **"표가 아니라 예제를
고치자"** 도 성립하지 않습니다 — 요청 예제는 이미 `ELEM_LIST`이기 때문입니다.

요청 키에 관해서는 **고칠 것이 없습니다.** 요청은 `ELEM_LIST`, 응답은 `AELEM`이고,
원문 세 곳이 그 상태로 서로 일관됩니다. 요청/응답 필드명이 다른 것은 이 API에서
드물지 않고, 이 아티클은 그걸 그대로 보여주고 있을 뿐입니다.

그래서 제안은:

1. **A-7은 철회**하는 쪽이 맞다고 봅니다. 지금 상태로 반영되면 표가 실제 API와
   어긋나게 됩니다.
2. 굳이 이 아티클에 대해 제보를 남긴다면 **`"SELETION_TYPE"` 오타** 쪽이
   실재하는 항목입니다.
3. 요청/응답 키가 다르다는 점은 결함이 아니라 문서 명확성 문제이므로, 필요하면
   별건으로 "요청 키와 응답 키가 다름을 본문에 명시해달라" 정도가 적절합니다.

**Jira는 저희가 손대지 않습니다.** 이 저장소의 규칙상 저자의 명시적 지시 없이는
MAPI 이슈를 생성하거나 편집하지 않습니다. 위 내용은 판단 재료로만 전달합니다.

## 5. 한 가지 덧붙임 — 원문을 다시 받아보시길 권합니다

요청서의 인용은 이 아티클 본문과 맞지 않는데, 인용된 `"AELEM": [1, 2]` 페이로드는
**저희가 실패 프로브로 보낸 요청과 정확히 같은 형태**입니다. 어느 쪽이든 위
`curl` 한 줄이면 30초 안에 갈립니다. 서로 다른 판본을 보고 있는 것이라면 그것
자체가 확인할 값어치가 있으니, 결과가 다르게 나오면 알려주십시오.
