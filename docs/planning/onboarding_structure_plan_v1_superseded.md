## 1. 기획 배경

`midas-nx 2.0.0`은 API 구현 범위, 테스트, CI, 안전 문서, 실제품 검증 기록 측면에서 상당히 성숙한 SDK다. 그러나 현재 정보는 개발자 관점에서 구성되어 있어 Python 초보 구조 엔지니어나 Excel 중심 사용자가 다음 질문에 빠르게 답하기 어렵다.

- 이 도구로 무엇을 할 수 있는가?
- 공식 MIDAS IT 제품인가?
- Python을 잘 몰라도 사용할 수 있는가?
- Excel과 함께 사용할 수 있는가?
- 내 모델을 실수로 변경하거나 삭제할 위험은 없는가?
- 무엇부터 설치하고 실행해야 하는가?
- 문제가 생기면 어디에 문의해야 하는가?

이번 개편의 핵심은 기능을 더 많이 보여주는 것이 아니라, 사용자가 자신의 수준에 맞는 입구를 선택하고 첫 성공 경험까지 길을 잃지 않도록 만드는 것이다.

## 2. 목표와 비목표

### 2.1 목표

1. 방문 후 1분 안에 SDK의 용도와 프로젝트 지위를 이해한다.
2. 사용자가 자신의 수준에 맞는 시작 경로를 선택한다.
3. 첫 튜토리얼은 모델을 변경하지 않는 읽기 전용 작업으로 구성한다.
4. 설치, 연결, 첫 조회의 각 단계에 예상 결과와 오류 해결 방법을 제공한다.
5. 고급 API 정보와 위험한 작업은 초보자 경로에서 분리한다.
6. 문서, 예제 코드와 실제 SDK 동작이 자동 테스트로 일치하도록 유지한다.

### 2.2 비목표

- 398개 endpoint를 첫 화면에 모두 노출하지 않는다.
- 초보자에게 HTTP, JSON, TypedDict 등의 개념을 먼저 학습시키지 않는다.
- 이번 단계에서 GUI 또는 Excel Add-in 전체를 개발하지 않는다.
- 공식 MIDAS IT 제품 또는 공식 기술지원 도구처럼 표현하지 않는다.
- 안전 검증 없이 생성·수정·삭제 튜토리얼부터 제공하지 않는다.

## 3. 핵심 사용자: 세 종류의 초보자

초보자를 단순히 “개발을 못하는 사용자”로 묶지 않는다. 익숙한 도구와 문제 해결 방식이 다른 세 부류로 나누고, 서로 다른 시작 경로와 산출물을 제공한다.

### 초보자 A — Python 초보자

- Python 기본 문법을 배우고 있거나 예제 코드를 조금 수정할 수 있다.
- `pip`, 가상환경, 환경변수, 패키지 import와 오류 메시지에 익숙하지 않다.
- 장기적으로는 Python으로 반복 업무를 직접 자동화하고 싶다.

필요한 것:

- Windows 기준 설치와 실행 안내
- 복사해서 바로 실행되는 짧은 예제
- 한 단계에 한 개념만 소개하는 튜토리얼
- 예상 정상 출력과 대표 오류 해결 방법
- 함수·입력 필드의 쉬운 한국어 설명
- CSV·Excel 저장 예제

첫 성공 목표: Python 스크립트로 연결을 확인하고 절점 데이터를 읽어 CSV로 저장한다.

### 초보자 B — VBA를 다룰 줄 아는 초보자

- Excel 표, 셀, 버튼과 VBA 매크로 작성에는 익숙하다.
- Python 환경을 별도로 관리하는 것보다 Excel 안에서 작업하기를 선호한다.
- HTTP, JSON, 인증 헤더와 REST API 설계에는 익숙하지 않을 수 있다.
- `midas-nx`는 Python SDK이므로 VBA에서 직접 import할 수 없다는 점을 먼저 이해해야 한다.

필요한 것:

- `VBA → 직접 REST 요청`과 `VBA → Python 실행 → midas-nx` 방식 비교
- Excel 표를 JSON 또는 Python 입력으로 변환하는 예제
- MAPI-Key를 셀과 코드에 평문 저장하지 않는 방법
- 버튼 이벤트와 API 로직을 분리한 예제
- 응답 JSON 파싱, timeout, 오류 표시 예제
- 행 단위 성공·실패를 Excel에 기록하는 패턴

첫 성공 목표: Excel 버튼으로 읽기 전용 Python 스크립트를 실행하고, 조회 결과를 지정된 시트에 가져온다.

권장 기본 경로는 `VBA에서 Python 실행 → midas-nx 사용`이다. 모든 endpoint 처리와 오류 로직을 VBA에 다시 구현하지 않는다. 단순 조회 한두 개만 필요하거나 Python 설치가 금지된 환경에서는 직접 REST 방식을 별도로 안내한다.

### 초보자 C — AI를 활용해 코딩하는 초보자

- Python 또는 VBA를 완전히 이해하지 못해도 AI에게 코드를 생성시켜 업무를 수행한다.
- 빠르게 결과를 만들 수 있지만 생성된 코드의 위험성, API 정확성과 보안 문제를 판단하기 어렵다.
- 잘못된 endpoint, 존재하지 않는 SDK 함수, 전체 삭제, 비밀키 노출과 무조건 재시도 위험이 크다.

필요한 것:

- AI에게 함께 제공할 공식 context 문서
- 검증된 프롬프트 템플릿
- 읽기 전용 작업부터 시작하는 단계별 프롬프트
- 생성 코드 검토 체크리스트
- 실행 전 위험 작업 탐지와 변경 미리보기
- 실제 모델이 아닌 mock 또는 복사 모델에서 시험하는 절차
- AI가 추측하지 않고 문서·타입·검증표를 확인하게 하는 규칙

첫 성공 목표: 제공된 프롬프트로 읽기 전용 코드를 생성하고, 체크리스트로 검토한 뒤 복사 모델에서 실행한다.

### 공통 원칙

세 경로의 사용자는 같은 SDK와 안전 기준을 사용한다. 설명 방식과 시작 도구만 다르게 제공하며, 서로 다른 API 로직을 중복 구현하지 않는다.

## 4. 개편 원칙

### 4.1 사용자 수준별 입구

모든 사용자를 하나의 긴 README로 안내하지 않는다.

```text
처음 방문
├─ Python을 배우면서 사용하겠습니다
│  └─ Python 설치 → SDK 설치 → 연결 확인 → 첫 데이터 조회
├─ Excel VBA를 활용하겠습니다
│  └─ 연동 방식 선택 → VBA/Python 브리지 → Excel 결과 확인
└─ AI에게 코드를 만들어 달라고 하겠습니다
   └─ 검증된 프롬프트 → 코드 검토 → 안전한 시험 → 실행
```

### 4.2 읽기 전용으로 첫 성공 경험 제공

첫 튜토리얼에서는 다음 작업을 금지한다.

- 새 프로젝트 생성
- 모델 열기 또는 교체
- 생성·수정·삭제
- 분석 실행
- 파일 덮어쓰기

첫 작업은 `verify_connection()`과 `Node.items()` 같은 읽기 전용 기능으로 구성한다.

### 4.3 업무 용어를 먼저 사용

| 개발자 표현 | 초보자에게 먼저 보여줄 표현 |
|---|---|
| endpoint | 사용할 기능 |
| payload | MIDAS에 보낼 데이터 |
| GET | 데이터 가져오기 |
| POST/PUT | 데이터 추가·변경하기 |
| exception | 오류 |
| timeout | 응답 대기시간 초과 |

기술 용어는 숨기지 않되, 설명 뒤의 괄호나 “기술 정보 보기”에 배치한다.

### 4.4 안전 수준 표시

모든 Recipe와 예제에 다음 중 하나를 표시한다.

- `읽기 전용`: 모델을 변경하지 않음
- `모델 변경`: 데이터가 추가되거나 수정됨
- `고위험`: 전체 삭제, 새 프로젝트, 파일 교체 또는 분석 실행

### 4.5 점진적으로 정보 공개

초보자 문서에는 필수 정보만 보여주고, 원본 요청·응답, endpoint 경로와 예외 클래스는 고급 설명으로 연결한다.

### 4.6 하나의 안전한 핵심, 세 가지 사용 방식

세 경로가 서로 다른 결과를 만들지 않도록 공통 업무 계층을 둔다.

```text
Python 초보자 ─ Python Recipe ─┐
VBA 초보자 ─── Excel/VBA UI ──┼─ 검증·미리보기·midas-nx ─ MIDAS NX
AI 코딩 초보자 ─ 생성 코드 ───┘
```

- Python 경로는 공통 업무 함수를 직접 호출한다.
- VBA 경로는 가능한 한 동일한 Python 업무 함수를 실행한다.
- AI 경로는 공통 Recipe와 context pack을 바탕으로 코드를 생성한다.
- 인증, 오류 처리, 제품 구분과 안전장치를 세 경로에서 각각 다시 구현하지 않는다.
- 같은 입력은 어느 경로를 사용해도 같은 검증 결과와 요청 계획을 만들어야 한다.

### 4.7 AI 코딩 전용 안전 규칙

AI가 만든 코드는 편의 예제가 아니라 검토되지 않은 코드로 취급한다.

- 존재하지 않는 함수나 endpoint를 추측하지 말고 설치된 버전의 문서를 확인한다.
- 처음 생성하는 코드는 읽기 전용이어야 한다.
- `delete_all`, `/doc/NEW`, `/doc/OPEN`, 파일 덮어쓰기와 자동 재시도를 탐지한다.
- MAPI-Key가 프롬프트, 코드, 로그 또는 채팅에 포함되지 않게 한다.
- 쓰기 코드는 변경 대상·개수·요청 내용을 먼저 출력하는 preview 단계를 갖는다.
- timeout 후 같은 쓰기 요청을 무조건 다시 보내지 않는다.
- mock → 폐기 가능한 모델 → 복사 모델 순서로 검증한다.
- “테스트 통과”와 “실제 MIDAS NX에서 안전함”을 같은 의미로 표현하지 않는다.

## 6. 문서 홈 화면 구성

문서 홈은 다음 순서로 구성한다.

### 6.1 한 문장 소개

> `midas-nx`는 MIDAS Civil NX와 Gen NX의 Open API를 Python에서 더 쉽고 안전하게 사용할 수 있도록 돕는 직원 주도형 오픈소스 SDK입니다.

바로 아래에 다음 고지를 짧게 표시한다.

> MIDAS IT가 공식 출시하거나 공식 기술지원하는 제품은 아닙니다.

### 6.2 “무엇을 하고 싶나요?” 선택 카드

1. Python을 배우면서 사용하고 싶어요
2. Excel VBA에서 사용하고 싶어요
3. AI에게 코드를 만들어 달라고 하고 싶어요
4. 지원 기능과 검증 상태를 확인하고 싶어요

### 6.3 3단계 첫 시작

```text
1. 설치
2. MIDAS NX 연결 확인
3. 모델 데이터 읽기
```

각 단계에는 예상 소요시간과 위험 수준을 표시한다.

### 6.4 대표 활용 사례

- 절점·요소·재료·단면 일괄 조회
- Excel 데이터와 모델 연결
- 반복 입력 자동화
- 해석 결과 수집과 보고서 작성

### 6.5 신뢰성과 한계

- 2.0.0 테스트 및 CI 상태
- 읽기 검증과 쓰기 검증의 차이
- 공식 제품이 아니라는 점
- 실제 모델 변경 전 사본을 사용해야 한다는 점

7. 안전 경고
8. 문서·지원·검증 링크
9. 개발자용 상세 정보

첫 코드 예제는 `doc.new_project()` 및 모델 생성 예제가 아니라 다음과 같은 읽기 전용 예제로 교체한다.

```python
from midas_nx import MidasClient, Product
from midas_nx.db.node_element import Node

client = MidasClient(product=Product.GEN)

print(client.verify_connection())
nodes = Node.items(client=client)
print(f"절점 {len(nodes)}개를 가져왔습니다.")
```

모델 생성 Quick Start는 “모델 변경 Recipe”로 이동하고 위험 수준을 표시한다.

VBA 경로에는 Python SDK를 VBA에서 직접 사용할 수 없다는 점과 권장 브리지 구조를 첫 화면에서 설명한다. AI 코딩 경로에는 프롬프트보다 먼저 실행 전 검토 체크리스트를 보여준다.

## 11. 오류 안내 구조

초보자 오류 문서는 HTTP 상태 코드가 아니라 사용자가 경험한 증상별로 구성한다.

### 권장 분류

- MIDAS NX에 연결되지 않음
- MAPI-Key가 없음 또는 잘못됨
- Gen/Civil 제품 선택이 잘못됨
- 모델이 열려 있지 않음
- 응답 대기시간 초과
- MIDAS NX 화면에 대화상자가 떠 있음
- NX PC에 경로가 존재하지 않음
- 요청은 전달됐지만 반영 여부가 불확실함
- 입력 데이터 필드가 잘못됨

### 오류 설명 템플릿

```text
무슨 문제가 발생했나요?
작업이 모델에 반영됐을 가능성이 있나요?
지금 무엇을 해야 하나요?
다시 실행해도 안전한가요?
기술 정보는 무엇인가요?
```

timeout이 발생한 쓰기 요청을 자동 재시도하라고 안내하지 않는다.

## 12. 전체 API Reference 개선

현재 reference는 대표 클래스와 일부 함수 중심이므로, 다음 정보를 자동 생성한다.

| 항목 | 표시 내용 |
|---|---|
| 기능 이름 | 사용자 친화적 이름과 원본 endpoint |
| 지원 제품 | Gen / Civil / Hyper-S |
| 지원 작업 | 읽기 / 생성 / 수정 / 삭제 |
| 검증 상태 | 미검증 / 실제 읽기 / 실제 쓰기 |
| 위험 수준 | 읽기 전용 / 모델 변경 / 고위험 |
| Python 위치 | import 경로와 클래스·함수명 |

| 주의사항 | 제품별 차이, timeout, 경로, 알려진 문제 |

초보자 문서에서는 업무 이름으로 검색하고, 개발자 reference에서는 endpoint와 클래스명으로도 검색할 수 있어야 한다.

## 16. 핵심 완료 기준

다음 조건을 모두 충족하면 초보자 온보딩 구조 개편을 완료한 것으로 본다.

- VBA 사용자는 직접 REST와 Python 브리지의 차이, 권장 방식과 제한을 설명할 수 있다.
- AI 사용자는 생성 코드가 검증된 코드가 아니라는 점과 안전한 시험 순서를 설명할 수 있다.

- 전체 API를 제품·메서드·검증 상태로 검색할 수 있다.
- 문서 코드와 링크가 CI에서 검증된다.
- 민감정보가 문서, 예제, 로그와 생성 파일에 남지 않는다.
